## 1. Authentication & Authorization

GlycoGourmet utilizes JWT (JSON Web Tokens) generated by the `users-permissions` Strapi plugin.

### 1.1 Local Authentication

**Endpoint:** `POST /api/auth/local`
**Description:** Authenticates a user and returns a JWT token.

**Request Body Payload:**
```json
{
  "identifier": "demo@glyco.com",
  "password": "demo_password"
}
```

**Response Payload (200 OK):**
```json
{
  "jwt": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "username": "demo_user",
    "email": "demo@glyco.com",
    "provider": "local",
    "confirmed": true,
    "blocked": false,
    "roleType": "admin",
    "isApproved": true
  }
}
```

### 1.2 Get Current User

**Endpoint:** `GET /api/users/me`
**Description:** Returns the authenticated user's profile data.
**Headers:** `Authorization: Bearer <JWT>`

## 2. Recipe Management Endpoints

All endpoints are prefixed with `/api/recipes`.

### 2.1 Fetch All Recipes (Catalog View)

**Endpoint:** `GET /api/recipes`
**Description:** Retrieves all published recipes with populated nested components.

**Supported Query Filters:**
- `populate=*`: Populates all component relations (ingredients, steps, nutrition).
- `filters[status][$eq]=published`: Retrieves only published entries.
- `publicationState=preview`: Bypasses default filtering to retrieve both drafts and published entities (Requires Admin/Author privileges).

**Example Request:**
`GET /api/recipes?populate=*&filters[status][$eq]=published&sort[0]=nutrition.glycemicLoad:asc`

### 2.2 Fetch Single Recipe by ID

**Endpoint:** `GET /api/recipes/:id`
**Description:** Retrieves a specific recipe by its unique slug ID.

**Example Request:**
`GET /api/recipes/low-glycemic-egg-salad-lettuce-wraps?populate=*`

### 2.3 Create Recipe (Draft / Published)

**Endpoint:** `POST /api/recipes`
**Headers:** `Authorization: Bearer <JWT>`

**Payload Example:**
```json
{
  "data": {
    "title": "My Personal Draft",
    "status": "draft",
    "publishedAt": null,
    "authorId": "patient@glyco.com",
    "isUserAuthored": true,
    "nutrition": {
      "glycemicLoad": 12,
      "glycemicIndex": 25,
      "netCarbs": 10,
      "fiber": 8,
      "kcal": 350
    },
    "ingredients": [
      {
        "ingredientId": "avocado-raw",
        "amount": 0.5,
        "unit": "cup",
        "prepState": "raw"
      }
    ]
  }
}
```

### 2.4 Update Existing Recipe

**Endpoint:** `PUT /api/recipes/:id`
**Headers:** `Authorization: Bearer <JWT>`

**Payload:** Same structure as POST. Used by Admin to change `status` to `published` and inject a timestamp into `publishedAt`.

## 3. Custom Ingredients Taxonomy

**Endpoint:** `GET /api/ingredients`
**Description:** Retrieves custom ingredients added by users or dietitians to supplement the USDA ground truth library.

**Endpoint:** `POST /api/ingredients`
**Description:** Submits a new custom ingredient into the pending audit queue for Dietitian verification.

---

## 4. Error Handling & Status Codes

- **200 OK / 201 Created:** Successful operation.
- **401 Unauthorized:** Missing or invalid JWT token.
- **403 Forbidden:** User lacks RBAC permissions (e.g. Standard user attempting to set `publishedAt`).
- **404 Not Found:** Requested entity does not exist.
- **500 Internal Server Error:** Strapi server crash or unhandled invariant violation.
